# Skin QA Checklist

## 공통 원칙
- 양쪽을 **동시에** 읽는다: 명세의 라우트 표 ↔ 코드의 `<Link to>`/`navigate()`/라우터 정의, 계약 문서 ↔ 타입 ↔ mock 시드 ↔ 화면이 쓰는 필드.
- 빌드 통과는 시작점일 뿐. dev 서버에서 실제로 클릭·입력·스크롤한다.
- 리포트: 심각도(치명/주요/경미/의심) → 재현 절차 → 기대/실제 → `파일:라인` → 스크린샷.

## 1. 정적 교차검증 (grep 기반)
- [ ] 라우터에 정의된 경로 전부가 명세 라우트 표에 있고, 반대도 성립
- [ ] 모든 `to=`/`navigate(`/`href=` 값이 실제 라우트와 매칭(동적 세그먼트 포함), 죽은 링크 0
- [ ] 계약의 엔드포인트 ↔ ApiClient 메서드 ↔ 훅 ↔ 사용 화면 1:1 매핑표 작성, 미사용/누락 표시
- [ ] 래핑 응답(`{items,total}`)을 훅/화면이 올바르게 꺼내는지
- [ ] 페이지 컴포넌트가 seed/mock을 직접 import하지 않는지 (`grep -r "seed" src/app`)
- [ ] 하드코딩 색/폰트(`#[0-9a-f]{3,6}`, `font-family:`, `Inter`) 검색 — 토큰 외 사용 목록화
- [ ] 관리자 코드가 사용자 번들에 섞이지 않음(빌드 청크 확인)
- [ ] 작업 파일 주석 0건, 짝 md 누락/고아 md 없음 (`code-annotation` 점검 명령)

## 2. 실측 (Playwright MCP)
- 폭 360 / 768 / 1024 / 1440 각각 스크린샷 → 가로 스크롤 발생 여부(`document.documentElement.scrollWidth > innerWidth`), 잘림, 겹침
- 각 화면의 상태: 로딩(mock 지연 중 스켈레톤), 빈 상태, 에러(`?mockError=1`), 권한 없음(비로그인으로 마이페이지/관리자 접근 → 리다이렉트)
- 핵심 흐름 E2E:
  - 웹: 메인 → 목록 필터/정렬(URL 쿼리 동기화, 새로고침 후 유지) → 상세 라이선스 선택(가격 변경) → 장바구니 → 주문 → 완료 → 마이페이지 다운로드 목록에 표시
  - 관리자: 로그인 → 스킨 등록 → 웹 목록/상세에 반영 → 주문 상태 변경 → 웹 마이페이지 반영
- Lenis: `lenis-smooth-scroll` 스킬 체크리스트 전 항목. 휠은 `page.mouse.wheel(0, 120)`을 수십 ms 간격 여러 번. 모달 열고 배경 스크롤 시도.
- 콘솔 에러/경고 0, 네트워크 실패 0(서버 단계)
- 키보드: Tab 순서, 포커스 링 보임, Dialog 포커스 트랩·Esc 닫기

## 3. 디자인 품질
- 명세·브리프와 비교: 섹션 순서, 위계(제목/본문 대비), 토큰 사용
- 한글 줄바꿈(keep-all), 긴 스킨명·가격 자리수 넘침, 이미지 비율 깨짐
- "AI스러운" 기본 배치 여부(skin-design-system 금지 목록)

## 4. 서버 단계 추가
- [ ] 각 엔드포인트 실제 응답 JSON ↔ 계약 ↔ http-adapter 반환 타입 비교(필드명·null 가능성·래핑)
- [ ] 금액 서버 재계산(클라이언트가 가격을 조작해 보내도 반영 안 됨)
- [ ] 비구매자 다운로드 URL 접근 차단, 만료 URL 재사용 불가
- [ ] 일반 회원 토큰으로 admin API 호출 → 403
- [ ] `.env`가 git에 포함되지 않음

## 정리
- 검증 중 만든 mock 주문/회원/스킨은 리포트 전 삭제하거나 mock 저장소 버전 리셋.
